Location extraction

Extract locations from txt file(s) using the Stanford CoreNLP NER extractor. Only available when input txt file(s) are selected.

More about input files and multi-name locations

Two types of input files are acceptable: txt or csv. When a txt file is selected, the script uses the NER values from Stanford CoreNLP to obtain a list of locations saved as a csv file, then processes that file like any csv of location names.

When a csv file is selected it can be: 1. a file containing a column of location names that need to be geocoded (e.g., New York); 2. a file of previously geocoded locations with at least three columns: location names, latitude, longitude; 3. a CoNLL table that may contain NER Location values.

To improve the geocoding of locations that can take multiple names (e.g., 'United States', 'US', 'USA'), the algorithm uses the entries of the multi_name_locations.csv file stored in the lib\wordLists subdirectory of the NLP Suite installation folder. You can edit that file to suit your specific needs.

Not available when selecting a CoNLL input csv file: the NER column is automatically used for CoNLL files.

Geocoding

Only available when a csv file of locations NOT yet geocoded is selected.

More about geocoding

'Split' locations (e.g., South America, Atlantic City) will be joined together for geocoding using the prefix values south, north, west, east, los, new, san, las, la, hong and the suffix values city, island. When using the CoNLL table as input, only two consecutive values will be joined together (thus, 'New South Wales' would not be joined).

To obtain more accurate results, select a country where most locations are expected to be: locations in the selected country of bias are PREFERRED by the geocoder over same-name locations in other countries (e.g., with United States selected, Florence, Rome, or Venice geocode in the United States rather than Italy).

Area and Restrict widgets are available only for Nominatim.

Nominatim is less accurate than Google, but Google requires an API key (see the Tips file).

For Nominatim, enter the latitude and longitude of the upper left-hand and lower right-hand corners of a rectangular area to privilege locations in that area (e.g., Rome, Georgia, vs. Rome, New York).

Restrict locations to the entered area only (otherwise it is just a preference).

Mapping

Default is Python folium pin map & heatmap. Google Maps requires a free API key with billing information (you are very unlikely to be charged at this scale).

More about Google API keys

You will need to get the API key from the Google console: https://developers.google.com/maps/documentation/embed/get-api-key. When selecting Google Maps, the API key field will become available. After entering the Google API key, click OK to save it and the key will be read in automatically next time around.

Opens the GIS_Google_Earth_main GUI after running the NER location extractor (and geocoder); you will then select as input the csv file produced by the extractor or geocoder.

Select the Google API key you wish to view, then click the button to open the config file to view/change the key.
